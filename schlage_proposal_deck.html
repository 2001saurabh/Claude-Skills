Engagement Overview

Consolidate, Standardise, Govern

Schlage's tracking spans two GTM containers, two regional domains, and two completely different purchase flows — currently managed independently with no shared standards.

⚠ Where Things Stand
Two GTM containers (GTM-K98NRXS7 & GTM-TNMQ8VX6) built and maintained independently — no shared naming conventions or publish governance
GA4 properties for schlage.com and schlage.ca have divergent event names — cross-market reporting is not directly comparable
shop.schlage.com (Shopify) — checkout steps, address entry, and payment have no adequate tracking today
Google Ads: no current access to verify conversion tracking accuracy or duplicate counting
BigQuery and Looker Studio not yet configured — raw event data being permanently deleted on GA4's 14-month rolling window
→
✓ Where This Leads
Unified GTM architecture — shared naming, folder structure, and Azure DevOps-managed publish workflow across both containers
Consistent GA4 event taxonomy — same event names, parameter names, and conversion definitions across US and Canada
Shopify checkout POC — feasibility confirmed first; if viable, purchase attribution flows back to GA4 via cross-domain stitching
Google Ads conversion tracking validated — no duplicate firing, smart bidding optimising on clean data
BigQuery export enabled + Looker Studio baseline — raw data preserved and cross-property reporting available for the first time
"The audit is the bridge. You cannot consolidate what has not first been documented. This engagement produces the baseline and the remediation plan — implementation follows as a separate phase."

Two completely different paths to purchase. Neither is fully instrumented end-to-end. Attribution is incomplete for both.

Flow A

Mechanical Locks: Knobs, Levers, Deadbolts, Handlesets, Electronic Locks

Change Management

How Azure DevOps Runs Tracking Governance

Once GTM containers are standardised, publishing is access-controlled and all stakeholders move to view-only. Azure DevOps becomes the single front door for every tracking change.

📥

Intake

New campaign, event, or site update submitted as an Azure DevOps work item with event name, trigger, property, container, and business reason

🔎

Triage

Assessed against governance standards: naming convention compliant? Which container (K98NRXS7 or TNMQ8VX6)? Consent category? Priority?

🛠

Build & QA

Implemented in GTM dev workspace. Tested with GA4 DebugView + GTM Preview mode. Validated against event taxonomy and SDR.

🚀

Publish

Published by approved publisher only. Every container version traceable to an Azure DevOps work item, a date, and a named owner.

🗓

Audit Trail

Quarterly GTM version review: what changed, who changed it, consent compliance status, impact on data quality.

"Tracking estates drift because changes arrive through side channels — a Teams message, an agency with publish rights, a one-off tag under deadline. Standardisation without a request process simply re-fragments within the year. Azure DevOps is the mechanism that holds the governance in place."
